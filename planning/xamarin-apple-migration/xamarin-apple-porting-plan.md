# Xamarin Apple documentation porting inventory

Assessed 2026-10-29. This is a proposed, static per-file porting plan, not a claim that the articles or linked samples already work on .NET.
The source archive is retained: **Drop means omit from the modern port, never delete the archived document.**

## Scope and evidence

- Archived conceptual source: [MicrosoftDocs/xamarin-docs@0506e3bf14b5](https://github.com/MicrosoftDocs/xamarin-docs/tree/0506e3bf14b520776fc7d33781f89069bbc57138).
- 591 Apple/shared/tooling files (581 Markdown articles/includes plus landing/navigation YAML); every selected source file has exactly one CSV/JSON row.
- Includes all docs/ios (including explicit watchOS dispositions), docs/mac, docs/cross-platform, docs/tools, and the general Xamarin introduction/installation entry points.
- 884 remaining Markdown/YAML files are listed in excluded-source-files.csv: Xamarin.Forms, Android, Essentials and generic Forms tutorials are outside this native Apple port, not proposed for deletion.
- API-reference XML is a different pipeline: maintained at dotnet/macios-api-docs; this is a conceptual-guide migration, not an API-doc rewrite.
- Sample mapping reuses the [2026-10-20 sample inventory](https://gist.github.com/rolfbjarne/d468157fc870fdd9a8fd178ee67a786a) and [dotnet/macios#20212](https://github.com/dotnet/macios/issues/20212); its decisions and dotnet-status fields are historical/static, not live port-completion signals.
- Source bytes are hashed per row. Sample URLs are extracted from each article; explicit matching roots are joined to the existing inventory. Missing sample URLs and unresolved mentions are reported, not silently treated as verified independence.
- Topic/path rules provide an initial disposition for every file. Priority is a proposed editorial queue; each actual port still needs its examples and current platform/API behavior checked.
- 35 current macios-maintained Markdown guides are assessed separately below and in macios-maintained-guide-inventory.csv, including explicit keep-in-repo decisions for contributor-only material.

## First docs-only batches

1. Platform landing pages and template tutorials for iOS, AppKit macOS, tvOS, and UIKit Mac Catalyst; link from hub/TOC and add accurate platform search metadata.
2. Shared Objective-C/C# concepts: delegates/protocols/events, native types, native references, memory/lifetime concepts and binding attributes. Prefer maintained macios source for the binding reference and diagnostics.
3. AppKit windows/menus/controls and tvOS focus/navigation, then UIKit controls/layout/accessibility. Rewrite outdated IDE steps and validate inline snippets against a generated native project; do not import historical sample solutions.
4. Merge already-modernized notifications, alternate icons, exception marshaling, Info.plist and filesystem content. Generalize/link applicable docs-maui articles rather than duplicate them.
5. Runtime/linker, deployment, profiling, and sample/service-dependent walkthroughs after the explicit prerequisites in their rows.

## Sample coordination contract

- One sample effort: [https://github.com/dotnet/macios/issues/20212](https://github.com/dotnet/macios/issues/20212). Do not create a second sample queue or port samples in this documentation task.
- For a P3 sample-driven page, hand off source_file, sample_references, sample_mapping, required platform/RID, and the user-visible behavior that must be demonstrated.
- Sample owner returns a canonical .NET source URL/commit and verification limits. Then the docs owner updates project paths, command output and screenshots and exercises the walkthrough against that commit.
- An archived sample marked Drop/Consolidate is not a request to revive it. Rewrite with a current template and self-contained snippets if feasible, or defer the walkthrough.
- Source sample inventory does not include every legacy recipe/Seminars/vendor dependency. These are retained in sample_references and must be resolved explicitly before any claimed runnable port.

## Port acceptance criteria

- A native SDK article belongs in docs-mobile; MAUI-specific framework behavior stays in docs-maui with cross-links. Proposed destination paths in the inventory are planning targets, not already-published URLs.
- Preserve attribution and applicable CC BY 4.0/MIT notices; check images and third-party material separately. Replace retired IDE screenshots, Xamarin installers, classic/Unified APIs and old CLI flags.
- Use released .NET/Xcode/workload combinations. Check NativeHandle and nint/nuint/NFloat changes and distinguish version-specific runtime/trimming behavior.
- Validate page links/xrefs/includes, snippet builds and documented user-visible behavior. Do not equate absence of mechanical legacy markers with technical correctness.
- Keep old URLs until an equivalent page exists; add targeted redirects through the publishing owner rather than blanket-redirecting the Xamarin archive.
- The four platform entry points, working first-app journeys and incoming links are the bounded closure milestone for dotnet/macios#17344; the full port queue is separate.
